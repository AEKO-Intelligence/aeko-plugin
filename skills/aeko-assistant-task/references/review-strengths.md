# Strengths in selected reviews

Use this mode only for `reviews.strengths_report.v1` with an `assistant-task-v1` Plan.md. Require `scope.selection={mode: explicit, resource: product_reviews, ids: [...]}` with 1–100 unique review IDs, and preserve `scope.store_product_id` when present. Read only the plan's `assistant_review` evidence IDs after claiming. The backend freezes original-language review text plus rating, language, platform, product and revision metadata and rechecks the current review/integration access. A missing or redacted selected review reduces coverage or blocks the task; do not fetch a broader review sample to replace it.

Find recurring customer-reported strengths in the selected evidence. Separate direct quotations or close paraphrases from your synthesis. A review can establish that a customer reported an experience; it cannot alone prove an objective product capability, clinical effect, universal outcome, or representativeness across all customers. Preserve distinctions between products and languages, and say when the selection is too small or mixed for a general claim. Do not translate away meaningful uncertainty in original-language text.

Write a concise report with selected count, reviewed count, any unread/unavailable count, the main themes, representative review evidence, and limitations. Cite each supported statement with `[evidence:<UUID>]`, where the UUID is a frozen evidence ID returned for this task. Include only evidence IDs actually cited in `aeko_save_action_output(kind=report_markdown, schema_version=assistant-output-v1, ...)`. The report is a saved analysis for user review. It does not track review suggestions, add prompts, generate ad copy, publish content, or change products. Complete only after the saved report is confirmed; reconcile an uncertain save with output reads before retrying.
